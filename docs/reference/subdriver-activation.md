# Sub-driver activation and rollback

This procedure is an operational handoff, not proof that an artifact was landed, installed, loaded or accepted by a live consumer. Main owns landing, installation, session operations and consumer readiness. Do not recover a foreign owner, interrupt a worker, rewrite history or repair reports as part of activation.

## Evidence and boundaries

Pin the exact delivered descendant commit and inspect its verification handoff before landing. Verify its required checks and ancestry against the current clean checkout; do not treat an intermediate merge or fixture commit as the final artifact. If the checkout moved, reintegrate and test through its owner rather than installing an obsolete build. Preserve baseline executable and discovery sources before landing. Keep historical failed checks visible even when a subsequent targeted correction has its own passing evidence. Tests of process reaping do not prove cleanup of external side effects; uncertain aborts retain recoverable state.

The watcher and bridge must remain compatible with both historical and canonical command, environment, role, JSON and notification spellings during a transition. A corrected fixture separates extension description from the create deadline; a stdout lifecycle repair validates trailing output through process completion within a bounded finish period. Verify the final artifact rather than inferring its behavior from a natural passing run or a parent-only commit. Live-provider tests are opt-in, not part of ordinary checks.

## Safe activation

1. Confirm the exact artifact, clean checkout, ancestry and final check results. Before landing, save the original executable, project watcher, global discovery symlink and its target bytes, and embedded bridge source in private deployment evidence outside the repository. Record hashes and build metadata. Do not copy live databases or worker transcripts.
2. Land only the authorized exact commit with a fast-forward after the baseline backups exist. Build the CLI from the clean landed checkout outside the tree; require its VCS stamp to match that commit without a dirty marker. Check watcher and bridge bytes against the landed tree. Do not replace pinned terminal or notification providers.
3. Revalidate intended session owners, watcher children, executable paths, discovery paths, current polling settings and absence of in-flight CLI operations. Do not infer claim state from a process list. Let short-lived calls finish naturally and leave active workers alone. Atomically install the verified executable with a same-directory temporary file and rename; recheck its bytes and stamp.
4. After backing up the original link, atomically replace the global watcher discovery symlink with one pointing to the tested project watcher. Do not overwrite a managed target, add a second watcher instance or change shared settings. Document that a configuration manager may restore the former link. Resource discovery must resolve to the intended single tested implementation.
5. Reload each identified session only after its watcher has normally acknowledged a successfully settled handling turn, with no pending claim, injection, renewal or CLI call. The session owner enters `/reload`; do not manufacture a boundary with lease expiry, manual drain/ack or forced interruption. Reload stops the old child, clears its in-memory claim state and starts a fresh watcher that rereads settings. Confirm the old watcher is gone, exactly one replacement belongs to the same owner, and its source, executable and polling values match the approved settings. Unknown identity, unexpected settings or duplicate children block the affected cutover.
6. Keep the request open until an ordinary real notification is handled and its exact claim settles normally with the expected repository label. File replacement and quiet process listings alone do not establish live readiness. Record evidence through owner-authorized read-only surfaces, without supervising descendants.

## Rollback

Retain the verified baseline and candidate executable and sources. At the same normal settled and unclaimed boundaries, restore saved watcher bytes and the original global symlink; document the deliberate difference from landed source. Reload only the identified sessions and verify one baseline child per owner with the approved current settings. Restore the baseline executable through a same-directory temporary copy and atomic rename, then recheck hashes, metadata and ordinary claim settlement. A compatibility fallback may continue draining while versions differ, but is not proof of full readiness.

Do not reset Git history, restart workers or sub-drivers, replace active generated bridges, change shared settings, or edit claims, endpoints, reports or databases. If an owner cannot reach a safe boundary or settings differ, leave compatible loaded code in place and report the bounded blocker instead of forcing rollback.
